# Codebase audit — 2026-06-13

Grounded sweep of the industrial repo (not a guess list). Severity: 🔴 fix soon · 🟡 worth doing · 🟢 nice-to-have.

## Findings

### ✅ RESOLVED — telemetry/readings disconnect (the meter→savings bridge)
The edge path (`/api/v1/ingest` → `telemetry` table) and the facility path
(`readings` table, read by shadow-savings) were not connected, so real device
data would never reach the savings page. Fixed: a savepoint-isolated bridge in
`/api/v1/ingest` mirrors each sample into `readings` when `facilities.site_id`
matches the device's site. See `docs/PILOT-ONBOARDING.md` and the migration
`backend/migrations/2026_06_add_facility_site_id.sql`.

### 🔴 Savings page shows fabricated numbers
`frontend/app/(dashboard)/savings/page.tsx` computes savings from hand-coded magic
numbers (`* 0.35`, `* 0.15`) disconnected from the real optimizer. For a tool shown
to hospitals this is a credibility risk — the number on screen isn't defensible.
**Fix (in progress):** new `/savings/shadow` endpoint replays real history through the
optimizer; the page now shows realized, defensible savings. See PRs from this date.

### 🔴 Device API key committed to a public repo
`edge/wokwi/prakriti_esp32.ino` has a live device key (`dk_102bf365...`) hardcoded
and committed. The repo is public, so anyone can post fake telemetry to
`sim-hospital-01`. Fine for the throwaway sim/demo, but **revoke it**
(`DELETE /api/v1/devices/{key_id}`) and mint a fresh key before any real pilot —
and never commit the next one (use a local config / env). The laptop-feeder and
LED demo reuse this same already-exposed key intentionally for zero-setup demo.

### 🟡 Demand charge uses a hardcoded month peak
`backend/api/v1/optimize.py:124` passes `month_peak_so_far_kw=0.0` with a TODO. This
makes the demand-charge term optimistic (assumes no prior peak this month). Real
month-to-date peak should come from the readings table. Affects savings accuracy.

### 🟡 Weekly PDF report not implemented
`backend/jobs/tasks.py:384` and `backend/api/v1/reports.py:24,36` are stubs. On the
roadmap (Phase 5). Needed for the pilot deliverable ("weekly report to the customer").

### 🟢 Report API endpoints are stubs
`reports.py` returns placeholders (no enqueue, no reports-table query). Fine until the
PDF job exists.

### 🟢 Two frontend hosts deploying in parallel
Vercel (~9 duplicate projects) and Netlify (`gleeful-elf-259dad.netlify.app`, in the
backend CORS allowlist) both build the frontend. Pick one. If Netlify is dropped,
remove that CORS line in `backend/main.py`.
